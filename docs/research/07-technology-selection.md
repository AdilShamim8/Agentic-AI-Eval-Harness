# Research 07 — Technology Selection

Date: 2026-09-12 · Status: complete · Decision record for v0.1

## D1. Language & runtime — Python 3.11+ (decided)

Ecosystem gravity (LangGraph/OpenAI/CrewAI all Python-first); 3.11 floor for
`tomllib`/typing maturity. Build env: 3.12.14.

## D2. Core dependencies — stdlib-first (decided)

- Core schemas: `dataclasses` + `json` (NOT pydantic). Rationale: zero-dependency
  install for CI speed and version drift immunity; our validation needs are bounded.
- YAML for benchmark configs: `PyYAML` (sole runtime dependency; ubiquitous).
- CLI rendering: `rich` if importable, graceful plain-text fallback (no hard dep).
- Live judge HTTP: stdlib `urllib.request` (no `openai` SDK dependency; works with any
  OpenAI-compatible endpoint via OPENAI_BASE_URL).
- Tests: pytest (dev dependency).
Trade-off accepted: hand-rolled schema validation is more code than pydantic; in
exchange the harness installs anywhere in seconds and cannot suffer pydantic major-
version breakage in CI. For a platform whose job is reproducibility, that wins.

## D3. Deterministic execution backend (decided)

`ScriptedModel`: seeded policy model emitting decisions (think/plan/tool_call/handoff/
final_answer/malformed) with skill/fault knobs. Real tools execute for real; answers
are composed from real observations. Purpose: bit-reproducible full-suite runs,
controlled fault injection, honest ablation attribution, zero API cost in CI.
All reports label `model_backend=scripted-policy-v1 (deterministic simulation)`;
live-LLM numbers are never implied. Live backends exist as interfaces (measured:
Not measured yet).

## D4. Benchmark registry — YAML files (decided)

Versioned YAML per benchmark: name/version/pattern, dataset path, evaluator list,
thresholds, execution settings, gates. Validated at load; registry is a directory,
not a service (git-friendly, CI-friendly).

## D5. Datasets — generated + committed + hash-verified (decided)

Seeded generator (deterministic, byte-identical output) emits 5 pattern datasets
(56 cases each, 280 total) with gold answers, golden trajectories, required/forbidden
tools, categories (normal/difficult/ambiguous/edge/adversarial/failure_inducing),
scheduled faults, injection markers. Manifest with sha256 per file; tests regenerate
and compare hashes. Hand-labeled calibration sample for judge reliability: author-
reviewed CSV (single-annotator limitation documented).

## D6. Reports — Markdown + JSON from same source (decided)

Markdown for humans/reviews; JSON (full run record) for tooling; both generated by
the same builder to prevent divergence. Failure taxonomy is a first-class column.

## D7. CI — GitHub Actions (decided)

ci.yml (lint/format/type/unit/integration on 3.11+3.12), eval-gate.yml (benchmark
validation + smoke eval + regression gate vs committed baseline — genuinely blocking),
security.yml (gitleaks + pip-audit + repo secret-pattern scan + injection tests).
Local Makefile mirrors every CI command so gates are verifiable pre-push.

## D8. Security — controls baked in, not advisory (decided)

Tool allowlists + forbidden-arg guards; network socket guard active during runs
(raises SecurityViolation); injection screening on task/tool outputs with audit log;
secret redaction at export; resource caps (steps/tool-calls/output chars/state bytes/
wall-clock). Threat model documented (docs/security/THREAT-MODEL.md).

## D9. Packaging — src layout, single console script (decided)

`agent-eval` console script; `pip install -e .[dev]`; release packaging script builds
release/ tree + zip + per-file sha256 manifest; clean-room validation script re-runs
tests + smoke eval from the extracted zip before delivery.

## Rejected alternatives

pydantic core (D2), notebook-driven eval (research 01), SaaS dependency (D7),
SQLite state store (file-based run records are git-reviewable; DB optional later),
async runner (determinism first; parallelism documented as extension).
