# Judge calibration artifacts

## What lives here

| File | Role |
|---|---|
| `sample.csv` | Exported calibration sample (case, task, gold reference, agent answer, judge verdict) — the blank form handed to a human annotator. |
| `hand_labels.csv` | The same sample after human labeling (`human_pass`, `annotator`, `notes` filled in). |

The recorded measurement derived from this pair lives in
`evals/results/experiments.json` (`calibration`): Cohen's κ = 1.0 (n = 56,
target ≥ 0.6 met; single annotator — `principal-eng`; limitation recorded).
`agent-eval calibrate --labels evals/calibration/hand_labels.csv` recomputes
κ from the pair; `agent-eval status` reports the recorded value.

## Provenance caveat (verified 2026-10)

This pair was exported from a **pre-finalization development state of the
react dataset**: the task texts in `sample.csv` / `hand_labels.csv` (e.g.
`react-norm-001`: "Compute 65 * 10 …") do **not** match the committed
hash-pinned golden dataset (same case id there reads "Compute 73 + 20 …"),
and `git log -S` confirms those task texts never existed in any committed
dataset revision. The pair was committed after the final dataset had already
been pinned, so it cannot be regenerated byte-identically from git history.

What this means in practice:

- The κ = 1.0 measurement is a valid historical measurement of judge–human
  agreement on those 56 cases as labeled; it is reproduced verbatim by
  `calibrate --labels` from the committed pair.
- It is **not** a measurement against the current golden dataset. A fresh
  calibration against the current hash-pinned dataset requires a new export
  (`agent-eval calibrate` exports a fresh sample from the current dataset)
  and a new human labeling pass — until then, treat κ = 1.0 as the recorded
  engagement-time evidence, with the revision gap stated above.
